# Remaining product work and security boundaries

Implemented code should not be mistaken for the entire requested product or an independently audited production system.

- Email verification and password reset are not implemented; there is no configured email delivery provider. There is no MFA, biometric gate, device-management UI or suspicious-login detection.
- The mobile core is implemented and can be type-checked/bundled. No APK, iOS archive, emulator interaction or physical-device release verification is claimed. Use web for advanced workflows currently absent on mobile.
- Budgets support explicit weekly/monthly/custom/salary-aligned periods and baseline projection. Automatic rollover, detailed budget editing UI, automatic salary recognition and comparative history views remain incomplete.
- Bill reminders are in-app schedules with explicit expense confirmation. Delivery of push/email/background notifications, recurring income, end dates, bill edits and recurring transfer payments remain incomplete. No worker is silently marking bills as paid.
- Goals track allocation history and progress. Editing goals, withdrawing/reallocating contributions, per-account earmarking and idempotency for allocation requests are remaining work. Do not retry an ambiguous allocation submission without checking its history.
- Deterministic insights currently cover budget thresholds and scheduled bills. Historical anomaly detection, configurable insight thresholds, trend comparisons, richer forecasts and a persistent notification inbox remain incomplete.
- CSV supports mapping, validation, reviewed commit and conservative duplicates. Automatic bank-specific debit/credit column mapping, date-format selection, CSV export, external bank identifiers and financial provider integrations remain incomplete. Do not import ATM withdrawals or repayments as expenses. Imports use source `csv`; no bank account access is implied.
- SMS now has an opt-in Android inbox reader, on-device parsing, clarification/review, optional remembered choices and audited corrections. It scans recent messages on request; it does not run a background receiver or auto-post financial records. Unsupported text needs manual correction. A native Android build and restricted permission grant are required; Play approval and physical-device behavior are not claimed. See [SMS review](SMS-REVIEW.md).
- Web speech recognition is browser-dependent and may use the browser vendor's servers. Type-to-review is always available. The simple parser proposes an amount, description and yesterday date; it does not robustly understand all Hindi date expressions, ambiguous numbers or categories. Review before confirming.
- AI is deliberately constrained to question interpretation and curated guidance selection; it is not an unrestricted generative financial adviser. English and basic Hinglish intent handling exist; full natural Hinglish responses are incomplete. The Groq adapter is tested with failures and controlled outputs; live account/model verification requires configured credentials.
- API ownership is enforced in every resource lookup, with additional composite database foreign keys. PostgreSQL row locks provide concurrency guarantees; SQLite is a local test/trial option only. There is no claim of end-to-end encryption, independent security audit, regulatory certification or fraud detection.
- The in-process bounded rate limiter is suitable for one small instance; it is not a durable/shared abuse prevention service. The web proxy causes backend auth requests to share the frontend's network address. Add reviewed trusted-proxy/client identification and a shared limiter before scaling.
- Strict refresh rotation can require signing in again when separate browser tabs race to refresh. Cookies are HTTP-only and Secure in production; a mobile refresh token is held in SecureStore. Access and refresh tokens are never put in browser local storage. Only theme preference uses local storage.
- Account balances aggregate all actual non-void ledger entries. Future calendar dates are rejected for transactions; recurring schedules represent future obligations. Opening-balance reconciliation/import ordering remains a user responsibility.
- Exports are bounded to 50,000 ledger records; larger accounts require an operator-assisted encrypted export. Large auxiliary tables need pagination/streaming before substantial scale. Backend request bodies are limited to 600 KB; CSV content to 500 KB.
- No cloud accounts were provisioned or deployed automatically. Database backups, retention, production alerting, recovery drills, HTTPS deployment verification and mobile release distribution are operator setup tasks.

Dependency audit results and actual command verification are recorded in [VERIFICATION.md](VERIFICATION.md). Do not run `npm audit fix --force` across an Expo SDK boundary without upgrading and testing the whole native dependency set.
